## What shipped

- Phase 10. `assets/exo-apt-decoder.js` detects a 2400 Hz AM envelope, aligns the NOAA sync bar, paints an uncalibrated thermal LUT (`calibrated: false`), and builds a geo overlay only when latitude, longitude, heading, and ground speed are finite and speed is above zero. Decode runs on the calling thread. A Web Worker is not started. `/radio/` shows `NO USB DEVICE` until `navigator.usb.getDevices()` returns a granted device.
- Phase 11. `assets/exo-adsb-ais.js` checks Mode S CRC-24 over the 112-bit word, decodes CPR, and checks AIS CRC-16. `tracksFrom` emits an air track only after a preamble hit and a CRC pass. `/maps/` shows `NO USB DEVICE` with no granted RTL-SDR.
- Phase 12. `assets/exo-mesh-router.js` drops a blank id, a spent TTL, and a duplicate, and draws a link only when RSSI or SNR is finite. The mesh page paints `STANDBY` and clears the graph to `#04070d`. Android `Router.summarize` shows `STANDBY` when the node list is empty.
- Phase 13. `functions/api/spaceweather.js` reads the NOAA planetary K-index column. A blank cell is null. Kp 0 stays quiet. foF2 and S4 are null because that product does not carry them, so MUF stays unmeasured. A failed fetch returns HTTP 200 with `ok: false` and nulls. The static preview has no `/api/spaceweather`, and `/radio/` and `/sentinel/` stay `OFFLINE`.
- Phase 14. `lib/sentinel-kinematics.ts` on vq projects a 15-minute centerline. Speed at or below zero, or a non-finite heading, returns null. Heading 0 with real speed is north. `sentinel-scan.ts` adds a pre-emptive fence hit only for an aircraft that is outside the circle, has speed above zero, and whose centerline enters the fence. Ships in the sea feed have heading and no speed, so they get no cone. The NWS features in this scan have no velocity, so storm cells get no cone. The look-ahead uses aircraft already returned for that fence box.
- Phase 15. `assets/exo-sitrep.js` seals a note with AES-GCM only when the grid is a real MGRS and the text is non-blank. There is no microphone capture, so the voice line stays `NO MEMO`. Android Room is version 2 with `MIGRATION_1_2` and no destructive fallback. The system screen reads the logbook and shows `NO OBSERVATIONS` when it is empty.
- Phase 16. `assets/exo-pip.js` uses `BroadcastChannel` `exopace-pip` and opens a window only from the PIP button. Headless Chrome has no Document Picture-in-Picture API, so the host stays `PIP UNSUPPORTED`. No HLS feed is pinned.
- Phase 17. `assets/exo-qr-beam.js` and Android `QrFountain` share the `EXO1` XOR frames. An empty payload encodes to nothing. CameraX plus ZXing decode a Y plane only. The scanner shows `NO CAMERA` without permission or a camera, and `NO QR FRAME` until a code is read. The camera feature is optional.
- Phase 18. `assets/exo-mavlink.js` parses MAVLink v2. A bad CRC returns null. GPS fix type below 2D is not a position. A footprint needs altitude above zero and a horizontal field of view inside (0, 180). With no granted serial port or Bluetooth device the maps and mission hosts stay `NO USB DEVICE`.
- Phase 19. `scripts/chaos-audit.test.mjs` covers empty and corrupt inputs. `assets/exo-throttle.js` leaves a missing Battery API at `NO BATTERY API` and 30 FPS. It sets `data-exo-fps` after `getBattery()` resolves.
